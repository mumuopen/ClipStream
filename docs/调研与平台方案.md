# ChopperBot 调研与融合平台方案

> 日期：2026-10-10 ｜ 状态：待用户确认后开工
> 本仓库目录名 `ChopperBot` 用于致敬原项目 [Geniusay/ChopperBot](https://github.com/Geniusay/ChopperBot)；本方案为"在其思想上重建"的融合平台设计。

---

## 0. 一句话结论

用 **Go** 重写一个「**直播录制 + 智能切片 + 搬运下载 + 翻译处理 + 多平台自动发布**」一体化平台：ChopperBot 只取其思想（插件化模块、弹幕热度分析、任务中心、账号矩阵路由），**所有重活交给成熟的子进程引擎**（yt-dlp / ffmpeg / whisper.cpp / rod 浏览器自动化），核心自身保持单二进制 + SQLite + Web 控制台，Windows 双击即跑，也可交叉编译扔到飞牛 NAS Docker。

## 1. ChopperBot 源码研读结论

源码已克隆至 `reference/ChopperBot/`（shallow clone，最后提交 2025-08-04 "Create License"）。

### 1.1 它是什么

"全自动多平台智能直播切片发布机器人"：发现热门直播 → 自动录制 → 弹幕分析找高光 → ffmpeg 切片 → GPT 生成标题/简介/标签 → 按账号人设路由 → 自动发布到抖音/B站。作者用它运营过一个千万播放量的B站切片账号（README 有展示）。

技术栈：Java 11 + Spring Boot 2.3.9 + Maven 多模块 + MyBatis + SQLite/MySQL + webmagic 爬虫 + Selenium + JavaCV。Java 侧约 2.6 万行，Vue3 控制台约 4.6 万行。

### 1.2 架构（值得记下的部分）

| 模块 | 职责 | 实现方式 |
| :- | :- | :- |
| File | 零依赖存储（JSON 文件 + 文件缓存池自动刷盘） | 自研 FileCacheManager |
| Creeper | 爬虫任务中心：任务封装/执行/记录/恢复 + 监控观察者 | TaskCenter + WebMagic/WebSocket LoadTask |
| Hot | 热门直播监控与推荐，按关注主播自动派爬虫任务 | Guard 循环 + 平台 adapter（斗鱼/虎牙/B站/抖音） |
| Live | 直播录制：FLV/M3U8 拉流写文件 | HTTP 流 64KB buffer 下载 + 3 次重试 |
| Barrage | 弹幕分析：打分曲线 → 高分区间 → 切片参考；**实时切片**（每 N 分钟 ffmpeg `-ss -to -c copy` 切一段并同步切弹幕） | 关键词词库打分（全局+主播级+ban 词）+ 分段策略 |
| Section / SectionWork | 切片执行 + AI 加工（标题/简介/标签，GPT API） | prompt 内置"营销号爆款标题"风格样例 |
| Account | 账号矩阵 + 人设标签 + **切片推送通道**（队列 + 路由规则匹配账号） | BlockingQueue + RouteRuler |
| Publish | B站走 **API 逆向**（upos 分片上传+封面+投稿）；抖音走 Selenium | B站通道较健壮，抖音通道硬编码 XPath |

插件机制：`模块 → 插件(Plugin) → 启动器(InitMachine) → 注册表(InitPluginRegister)`，带依赖检测、循环依赖检测、拓扑启动顺序、Guard 线程池（长驻循环任务）。这套自研"迷你 IoC + 生命周期"体系是全项目最有设计感的部分。

### 1.3 值得借鉴的 6 点

1. **任务中心统一收口**：所有异步动作（爬/录/切/发）都封装成 Task 进队列，可记录、恢复、监控——我们的 Job/Pipeline 队列照此思路做。
2. **弹幕密度高光检测**：关键词打分曲线 → 高分区间 → 切片候选。这是"无 ASR 时代"的高光检测方案，便宜、实时，应保留为一路信号。
3. **实时切片**：录制中每 N 分钟无重编码切一段（`-c copy`），直播结束即可进入分析，不用等整场录完。
4. **账号人设路由**：切片打好标签后按"账号人设"（LOL搞笑/Apex操作）路由到不同账号发布——矩阵号运营的核心抽象。
5. **B站发布走 API 逆向**（upos 分片直传），比浏览器自动化快且稳；值得作为 B 站的"快通道"保留。
6. **零数据库依赖哲学**：能 JSON 文件就 JSON 文件（我们升级为 SQLite，但"开箱即用零外部依赖"的精神保留）。

### 1.4 必须抛弃的 5 点（硬伤）

1. **发布选择器硬编码**：抖音发布用绝对 XPath（`/html/body/div[2]/div[1]...`）+ 硬编码 chromedriver 路径，平台一改版全挂。→ 必须改为**配置化选择器 + 登录态目录 + 可视化排障**。
2. **JavaCV 逐帧重编码**：切片走 grabber→recorder 逐帧转码，一场几小时的 FLV 切片极慢。→ 全部用 ffmpeg 子进程，能用 `-c copy` 就 copy。
3. **只能 IDE 里跑**：无打包产物、配置写死本地路径，这直接违背"人人可搭建"的初衷，也是你当年弃用的直接原因。
4. **Spring Boot 2.3 / Selenium 4.0 老旧**，且项目 2023-08 后无实质更新（CHANGELOG 停在 V1.0.11，2025-08 仅补了个 License）——**思路可继承，代码不可依赖**。
5. **AI 侧只有"标题生成"一个点**：没有 ASR 转写、没有 LLM 内容理解、没有翻译。而这恰是 2024-2026 这几年的最大增量。

## 2. 2024–2026 生态调研结论

### 2.1 各环节现成轮子（全部活跃维护）

| 环节 | 项目 | 语言/形态 | 证据（2026 年时点） | 我们怎么用 |
| :- | :- | :- | :- | :- |
| 点播下载 | **yt-dlp** | Python 独立 exe | 约 16 万星；支持数千站点、`--cookies-from-browser`、SponsorBlock、字幕提取（B站/YouTube 文章 2026-05） | **引擎①**：Go 子进程调用，不碰其 Python 内部 |
| 直播录制 | **DouyinLiveRecorder** (ihmily) | Python，FFmpeg 拉流 | 60+ 平台、弹幕录制完整率 99.7%、循环值守（多篇 2025-12~2026-07 实测文） | 平台流地址解析逻辑的参考实现 |
| 直播录制 | **bililive-go** | **Go**，C/S + Web UI | 20+ 平台，2026-01 仍在更新（层级配置/Telegram/ntfy 通知/抖音弹幕） | **同语言先例**，直播模块可大量参考其平台解析代码 |
| ASR | whisper.cpp / faster-whisper / sherpa-onnx(SenseVoice) | C++/Python/ONNX 独立二进制 | 三者均活跃；faster-whisper CPU 近实时（2026-10 实测文）；sherpa-onnx 端侧成熟 | **引擎②**：接口抽象，默认 whisper.cpp（零 Python 依赖），可切 faster-whisper/sherpa-onnx |
| AI 切片 | **AutoClip** (zhouxiaoka) | FastAPI+Celery+Redis+React | 2026-10 上 GitHub Trending（网易/百家号报道）；流水线=下载→大纲→时间线→评分→标题→切片→合集；**B站上传仍是"开发中"** | 直接对标竞品；其"发布环节缺失"正是我们的差异化空间 |
| AI 切片 | ai-highlight-clip (toki-plus) | PyQt 桌面 | Whisper + LLM 评分 + 标题（2026-01） | 同思路验证 |
| 内容生成 | **MoneyPrinterTurbo** (harry0703) | Python | 约 7.2 万星，v1.2.8（2026-05）：LiteLLM 100+ 模型、9 种 TTS、WebUI/API/CLI | 证明"主题→文案→素材→配音→成片"管线化可行；TTS 引擎选型参考 |
| 自动发布 | **social-auto-upload** (dreammis) | Python + Playwright | 支持 抖音/B站/小红书/快手/视频号/百家号/支付宝生活号/微博/虎扑/TikTok/YouTube，2026-03 仍有提交 | **引擎③的教科书**：各平台上传器的选择器与流程直接参考移植到 rod |
| 浏览器自动化 | **rod** (go-rod) | **Go** CDP | 7000+ 星、100% 测试覆盖、无驱动、元素自动等待（腾讯云 2026-07 评测）；chromedp 亦可 | **引擎③本体**：发布模块核心依赖 |
| 商业对标 | 极睿 iCut 等 SaaS | 商业 | "直播未结束切片已发布"已成电商标配（2025-11 报道） | 赛道被市场验证，且 SaaS 定价给自建留了空间 |

### 2.2 相比 2023 年 ChopperBot 时代，什么变了

1. **LLM API 普及且便宜**：高光检测从"弹幕密度单信号"升级为"**弹幕密度 + ASR 转写 + LLM 语义理解**"三信号融合，准确率量级提升。
2. **ASR 彻底离线化**：whisper.cpp / faster-whisper / sherpa-onnx 让 CPU 机器就能转写几小时视频，无云端成本（符合自持算力偏好）。
3. **浏览器自动化成熟**：CDP 系（rod/Playwright）取代 Selenium，支持持久化 user-data-dir 登录态、stealth 反检测、元素自动等待——发布稳定性比 XPath 时代高一个量级。
4. **平台风控同步加强**：抖音等对自动化发布敏感，需要"真人环境 + 低频 + 人工审核门"策略，纯 API 逆向通道风险升高。
5. **yt-dlp 一统下载**：数千站点一个工具搞定，自写解析器的时代结束了。

### 2.4 2026-10-10 晚补充甄别（12 项短视频工具）

用户从短视频收集了 12 个工具/模型，已逐项验证并下载至 `.temp-ck/`，详见 **《短视频工具甄别.md》**。落地结论：
- **M3 配音双引擎定案候选**：OmniVoice（k2-fsa，0.8B，600+ 语言克隆，Apache-2.0，8G 显存）为主力，Audio8 TTS 0.1B（ONNX INT8，CPU 可跑）为轻量备胎
- **M3 BGM 引擎**：ACE-Step（Apache-2.0，3.5B/v1.5，8G 显存）
- **M2 发布参考**：social-auto-upload（已下载）+ OpenShorts 的竖屏智能排版思路
- **复杂成片出口**：剪映草稿协议（参考 jianying-editor-skill，MIT）作为 process 模块可选精修出口
- **解说管线参考**：NarratoAI（10K 星，DeepSeek 可用，取管线与 prompt 设计）
- **动效生成新引擎范式（2026-10-11 出处确认）**：PDoomVideo（Claude Opus 5.5 那支出圈 MV 的源码，2.0K 星）——"LLM 写 p5.js/Canvas 代码 → headless Chrome 逐帧渲染 → ffmpeg 合成"，与我们的 rod+ffmpeg 栈天然契合，M3+ 可选引擎；通用底座 ClaudeAnimationBase 一并入库
- **工作流思想借鉴（2026-10-11 出处确认）**：DeterminFlow（893 星，AGPL，笔枢写作的 AI 小说生产运行时）——不整合（Python/React+AGPL），但采纳其"节点级上下文隔离、按节点 token 记账、结构化校验+定向重试、断点恢复"到我们 pipeline 的 LLM 阶段；小说内容线可用其桌面版+bishu-novel 插件+DeepSeek key 做文字生产上游
- **不采用**：ESP-Skainet（ESP32 专用）、NVIDIA VoiceChat 11B（11B 塞不进手机、非评分器；观语跟读改走 GOP 发音评估路线：speechocean762 + GOPT）

## 3. 语言选型：**Go**（定案）

| 维度 | Go ✅ | Rust | Python | Java（原版） |
| :- | :- | :- | :- | :- |
| 部署 | **单二进制**，Windows 双击/NAS Docker scratch 镜像 | 单二进制，但交叉编译+构建链重 | 解释器+venv+pip，环境地狱 | JVM + Maven，你已弃用 |
| 并发管线 | goroutine + channel 天然适合多任务流水线 | async 复杂，Tokio 学习曲线 | GIL，进程池别扭 | 线程池样板代码 |
| 子进程引擎编排 | `os/exec` 一流（我们 80% 的活是编排引擎） | std Command 够用 | subprocess 够用 | ProcessBuilder 别扭 |
| 浏览器自动化 | **rod（7000+星）/chromedp 成熟** | chromiumoxide/thirtyfour 生态弱 | Playwright 最强 | Selenium 老旧 |
| 直播录制先例 | **bililive-go（20+平台）** | 少 | DouyinLiveRecorder 最全 | ChopperBot 自己 |
| SQLite | modernc.org/sqlite **纯 Go 无 cgo**，交叉编译无痛 | rusqlite 需 cgo 或绑定 | 内置 | JDBC |
| 开发迭代速度 | 快，单人可维护 | 慢（你写 IO 编排型平台，Rust 性能收益≈0） | 快但工程化弱 | 慢 |
| AI 生态 | 弱 → **但用子进程引擎规避**（whisper.cpp 独立二进制等） | 弱 | 最强 → yt-dlp/ASR 作为引擎保留其价值 | 弱 |

**结论**：本平台本质是"**IO 编排型**"系统——下载、录制、转码、发布全是 IO，CPU 密集部分全部交给 ffmpeg/ASR 引擎。Go 按单二进制部署 + goroutine 管线 + rod 浏览器自动化 + bililive-go 先例，四票齐投；Rust 的性能优势在这个形态里兑现不了，反而拖慢迭代。Python 生态最强但违背你的"轻"要求——**yt-dlp、faster-whisper 等 Python 精华以独立 exe/子进程形态继续为我们服务，但平台本体不写 Python。**

### 3.3 候选语言考察清单（用户点名：Erlang / C / C++ / 其他）

| 语言 | 亮点 | 本项目中的判定 |
| :- | :- | :- |
| **Erlang/Elixir** (BEAM) | 进程模型最强：百万级轻进程、容灾、热升级，长连接/高并发服务的王者 | 浏览器自动化断手：CDP 绑定无成熟生态（已验 2026-10，主流方案只有 Python/JS/Java/Go/.NET 有）；Web 控制台生态弱；部署要 BEAM 运行时（不轻）；它把优势用在"消息推送/直播弹幕分发"这类场景——那是 pushme-server 的主场，不是视频工厂的主场 |
| **C/C++** | 性能天花板、零运行时、IO 最底层 | 浏览器自动化无主流绑定（Playwright 无 C++ 版，CDP 绑定不成熟）；Web/JSON/SQLite/SSE 全部手搓；迭代慢一个量级。它的正当用法是"自己重写 ffmpeg/whisper 引擎"——我们恰恰是引擎的使用者，不是造引擎的人 |
| **TypeScript/Node** | Playwright 原生支持、异步顺手、写爬虫/长任务舒服 | 部署=Node 运行时+node_modules，违背"单文件/轻"；CPU 型长任务（字幕烧录调度等）易卡事件循环；工程化依赖多。可留作"控制台前端"的备选技术，核心平台不用 |
| **Rust / Python / Java** | 已在 3.1 表内对比 | 见上表 |

> 结论不变：**Go 是这个"编排器"形态的工业折中点**——开发效率≈动态语言、部署≈静态语言、并发≈为网络服务而生，且浏览器自动化（rod/chromedp）与直播录制（bililive-go）都有同语言成熟先例。这不是口味偏好，而是可验证的事实。

### 4.2 核心抽象（对齐 ChopperBot 思想，砍掉其复杂度）

| ChopperBot 概念 | 本平台对应 | 简化点 |
| :- | :- | :- |
| Plugin + InitMachine + 注册表 + 依赖拓扑 | **Adapter 接口 + 注册表（编译期）** | Go 不搞动态热插拔（plugin 包在 Windows 上基本不可用），接口注册 + 配置组合即可获得 90% 的扩展性 |
| GuardPlugin 长驻循环 | goroutine + context 取消 | 天然 |
| ConfigFile 文件插件 | SQLite + 单一 YAML 配置 | 保留"零外部依赖" |
| TaskCenter | Job Queue（SQLite 持久化） | 自研轻量队列，接口预留未来换 asynq+Redis |
| 弹幕打分曲线 | **三信号融合高光**：弹幕密度（保留）+ ASR 转写 + LLM 评分 | 升级 |
| 账号人设路由 | 账号池 + 标签路由（照抄思想） | 一致 |

### 4.3 模块与目录

```
├── internal/
│   ├── core/                      # Job、Pipeline、队列、事件总线
│   ├── store/                     # SQLite（modernc.org/sqlite，纯 Go）
│   ├── engine/                    # 子进程引擎适配层
│   │   ├── ytdlp/  ffmpeg/  asr/  llm/
│   ├── live/                      # 直播监控/录制/弹幕（参考 bililive-go）
│   ├── ingest/                    # 点播下载（URL/列表/频道）
│   ├── understand/                # 转写→高光评分→翻译→SRT/ASS 字幕
│   ├── process/                   # 精剪、拼接、竖屏重排、封面、烧字幕
│   ├── publish/                   # rod 发布器 + 平台选择器配置 + 账号池
│   ├── notify/                    # pushme / webhook
│   └── web/                       # HTTP API + SSE + embed 控制台
├── web/                           # 控制台前端（先 htmx 轻量实现，可后换 Vue）
├── configs/                       # 平台选择器 YAML（改版只需更新配置）
├── docs/
└── reference/ChopperBot/          # 原版源码，仅供研读（gitignore）
```

### 4.4 四条核心管线（配置即管线，阶段可插拔）

1. **搬运转译管线**（YouTube/海外 → 国内）：
   `yt-dlp下载(--cookies --proxy 7897) → ASR转写 → LLM高光评分+切片点 → LLM翻译 → ffmpeg精剪+9:16重排+双语字幕烧录 → 审核台 → 发布`
2. **直播切片管线**（ChopperBot 本命）：
   `监控开播 → 录制(FLV/HLS+弹幕) → 实时分段(-c copy) → 弹幕密度+转写双信号高光 → 切片+标题/标签 → 按账号人设路由 → 发布`
3. **本地加工管线**（手头素材直接进厂）：
   `本地文件 → 转写 → 高光/整段处理 → 烧字幕/配音 → 发布`
4. **定时矩阵管线**（运营态）：
   `成品库 → 定时调度 → 多账号错峰发布 → 数据回收（播放/点赞）→ pushme 日报`

### 4.5 关键技术决策

- **发布**：rod（CDP）+ 每平台一个 `configs/platforms/*.yaml` 选择器配置 + 独立 `user-data-dir` 登录态目录（首次扫码登录后长期复用）+ 发布前截图存档（排障/审计）。B 站额外保留 **upos API 直传快通道**（ChopperBot + social-auto-upload 双参考）。**发布默认挂人工审核门**，风控敏感期可全自动。
- **ASR**：接口抽象，默认 **whisper.cpp**（单文件二进制、零 Python）；faster-whisper、sherpa-onnx(SenseVoice) 作可选引擎。字幕产出 SRT/ASS 双格式。
- **LLM**：OpenAI 兼容 API（你现有的 key 都能用）+ ollama 本地通道（自持算力选项）。用途：高光评分、切片点选择、标题/简介/标签生成、翻译。
- **代理**：全局可配（默认 `127.0.0.1:7897`），按引擎生效——yt-dlp、LLM API、YouTube 拉流走代理；国内平台不走。
- **通知**：pushme 深度集成（你的自建推送），节点：任务完成、需要人工审核、发布成功/失败、直播开播提醒。
- **部署**：Windows 主力（`go build` 单 exe）；飞牛 NAS Docker（交叉编译 linux/amd64 + 最小镜像，ffmpeg/yt-dlp 挂载进容器）。
- **合规**：平台内置"素材来源标注/授权字段"，二创与搬运优先走授权素材与自有内容；发布频率限制防风控。

### 4.6 与你现有资产的协同

- **FanyiStudio**（HeyGen 面向客户交付）：GuanClip 是自用自动化管线，翻译模块互补不冲突。
- **观湛AI视频 / 观语**：品牌家族沿用"观"字命名；观语的 sherpa-onnx 经验直接复用到 ASR/TTS 引擎。
- **pushme-server**：作为通知基建复用。
- **飞牛 NAS**：7×24 录制与定时发布的部署位。

## 6. 风险与对策

| 风险 | 对策 |
| :- | :- |
| 平台改版导致发布选择器失效 | 选择器全部配置化（非硬编码），失效时截图+通知，人工 5 分钟修配置；B站保 API 快通道 |
| 自动化发布触发风控/封号 | 真实 Chrome + 持久登录态 + 低频 + 随机间隔 + 人工审核门默认开启 |
| 搬运的版权问题 | 来源授权字段强制填写；优先自有内容/授权素材/跨语种翻译（转化性更高）；风险平台默认水印与出处标注 |
| 直播流地址解析随平台变动 | 参考 bililive-go / DouyinLiveRecorder 双实现的解析逻辑，adapter 化便于跟修 |
| yt-dlp 更新频繁 | 引擎版本锁定 + 一键升级命令，下载失败自动提示升级 |
