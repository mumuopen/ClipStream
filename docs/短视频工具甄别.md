## 1. NVIDIA NemotronLabs VoiceChat 11B（观语重点考察项）

**真身**：`huggingface.co/nvidia/NVIDIA-NemotronLabs-VoiceChat-11B`，2026-08-03 发布，OpenMDW-1.1 协议，**仅英文**。

**它是什么**：端到端全双工语音**对话**模型——FastConformer 语音编码器(0.6B) + Nemotron Nano v2 9B LLM 主干 + NVIDIA TTS 解码器/编解码器 = 11B 总参。~450ms 轮替延迟，支持自然抢话（barge-in）和工具调用，VoiceBench 开源全双工第 2 名。代码：github.com/NVIDIA-NeMo/Speech。

**能不能塞进手机做"跟读检查"？—— 不能，而且用错了工具**：
1. **塞不进**：9B LLM 主干 + 语音编解码全栈，fp16 约 22GB、int4 也要 7GB+，旗舰手机 RAM（12-16GB）装不下，功耗与延迟也不满足端侧体验。这类模型的部署位是服务器 GPU。
2. **形态不对**：它是"对话"模型，输出的是语音回复，不是结构化的发音评分。跟读检查需要的是**音素级/单词级打分**（哪个音发错了、准确度/流利度/完整度多少分），这要用专门的发音评估技术。
3. **语言受限**：仅英文（对观语够用，但前两条已否决）。

**观语跟读检查的正确技术路线**（按成本递增）：
- **零成本起步**：观语已有 sherpa-onnx 离线 ASR——把用户跟读音频识别成文本，与目标句做词级对齐对比，给出"读对了几个词"的粗糙分。够 MVP。
- **正规方案**：**GOP（Goodness of Pronunciation）发音评估模型**。现成资源：speechocean762 数据集（小米×海天瑞声开源，5000 句、250 位中国人英语、音素级人工评分）+ **GOPT**（ICASSP 2022，Transformer 多粒度发音评估开源项目）。可训练/导出 ONNX 端侧跑，模型小（几 MB~几十 MB），完全离线。
- **云端方案**：Azure 发音评估 / 腾讯云 SOE（按量付费，体验最好但违背离线原则，可作可选增强）。
- VoiceChat 11B 的真正对路场景是观语的"**AI 口语陪练**"（自由对话），且只能做成云端服务（服务器 GPU + API），将来做云陪练时再考虑。

## 2. PDoomVideo ——已确认（2026-10-11）："LLM 写代码渲染 MV"范式的源码本体

**真身**：`JohnHeibel/PDoomVideo`（2.0K 星 / 211 fork）。这就是 2026-10 那条热点——Claude Opus 5.5 生成整支 MV《I'm Upping My P(doom)》——的**源码仓库**（歌名里的 P(doom) 即项目名由来）。整支 3:56 动画 MV 分两代生成（`legacy/` 为第一代），人类只给两条指令：用 Clawd 角色设计、给每句歌词配有趣画面与转场。

**技术架构（值得抄的完整范式）**：
- LLM 产出 `STORYBOARD.md`（逐镜头规划）+ `ANIMATION_GUIDE.md`（给并行子代理的风格/代码指南）
- `src/ch/` 九个章节，每章一个 p5.js 场景文件；共享代码含角色/道具/歌词/时间线
- `studio.html`（p5.js + p5.brush 画布）→ `render.mjs` 用 **headless Chrome 逐帧绘制**（`--frames=0:156.6 --workers=4`，可断点续渲）→ **ffmpeg 合成 MP4**
- 运行要求：Node.js + Chrome + ffmpeg（歌曲在 `assets/pdoom.mp3`）

**对本平台**：这不是拿来即用的工具，而是一种新引擎形态——**"代码渲染动画"**：LLM 写 Canvas/HTML 动效代码 → 无头浏览器逐帧截图 → ffmpeg 合成。确定性渲染、零模型权重、可无限重跑微调，适合片头/转场/歌词动效/插画型内容。与我们平台天然契合：**M2 已引入 rod（Go 的 CDP 库）**，rod 截帧能力 + DeepSeek 写代码 + ffmpeg 合成即可复刻该范式。作者还开源了更通用的底座 **ClaudeAnimationBase**（"更可靠、更通用的 Claude 动画基座"）。排期：M3+ 可选"动效生成"引擎。✅ 两个仓库均已下载。

## 5. "concat"（≈CapCut/剪映）——自动化剪辑生态已存在

解读：你说的应是 **CapCut/剪映** 这类本地剪辑工具 + "帮模型写方法（skills/MCP）"。这个生态 2026 年已经现成：
- **jianying-editor-skill**（luoluoluo22，3.9K 星，MIT）：让 Claude Code/Cursor/Trae 等 Agent 用自然语言操作剪映——底层是**直接生成剪映草稿协议 `draft_info.json`**（基于 pyJianYingDraft），支持素材导入/AI 配音/字幕/配乐/特效/录屏智能变焦/网页动效转视频/影视解说；自动导出靠 Windows UI 自动化（剪映 ≤5.9 最稳）。
- **jianying-mcp**（hey-jian-wei）：MCP 服务器版本，任意支持 MCP 的 LLM（含 DeepSeek）可接入。

**对本平台的双轨决策**：
- 常规切片/字幕/竖屏重排 → **自研 ffmpeg 管线**（M1 已在做，稳定可控）。
- 需要剪映级花字/特效/模板的成片 → **导出剪映草稿**（借鉴 jianying-editor-skill 的草稿协议封装，Windows 端 UI 自动化导出），作为 process 模块的可选"精修出口"。
- DeepSeek API key 完全可用：它兼容 OpenAI 接口，我们平台的 LLM 引擎层直接支持（config.llm 填 DeepSeek 端点即可）。✅ 两个仓库均已下载。

## 6. DeterminFlow ——已确认（2026-10-11）：面向生产的 AI 工作流运行时

**真身**：`alikon-art/DeterminFlow`（893 星 / 135 fork / 118 commits，**AGPL-3.0**，活跃）。不是"小说转视频"工具，而是**把 LLM、脚本、API、人工审批组织成有版本、可校验、可重试、可恢复、可审计工作流的运行时框架**。你听到的"小说流程"来自其生产验证案例：[笔枢写作](https://bishuxiezuo.cn/) 的 AI 小说正文生产链路（导演→世界状态→角色维护→多写手→整合→校验→渲染→落库），官方插件 `bishu-novel` 已开源该工作流。

**核心卖点**：
- **节点级上下文隔离**：每个 Agent 节点只看自己需要的上下文——真实任务（11 个模型会话，17.6 万 token）比单智能体长链估算**节省 70-89% Token**（长链最高达 9.1 倍）
- **失败不重来**：从失败节点恢复重试，已完成部分不重跑；跨进程重启有检查点
- **按节点记账**：每节点/每次尝试/每次模型调用独立 token 账本；结构化输出校验+自动修复+定向重试
- 形态：Python 3.11 + FastAPI + React 控制台 + Windows/macOS 桌面安装包 + Docker；**支持 `DEEPSEEK_API_KEY`（你的 key 直接用）**；MCP/Skill/Plugin 生态

**对本平台的判定（两层）**：
1. **不整合进平台**：它是 Python/React 全套运行时且 AGPL-3.0 传染，Go 平台不嵌它。
2. **两个正确用法**：
   - **思想借鉴**：节点级上下文隔离、按节点 token 记账、结构化校验+定向重试、断点恢复——正是我们 pipeline 的 LLM 阶段（高光评分/标题/翻译）该长出的能力，M3 落地时参考其设计；
   - **独立工具**：若开"小说/短剧解说"内容线（小说批量→解说文案/短剧脚本→喂给 ChopperBot 剪辑），可直接用它的桌面版（装 bishu-novel 插件 + DeepSeek key）做**文字生产上游**，产出的文案从"本地加工管线"入口进平台。✅ 已下载。

（附注：此前猜的 AI-NovelFlow 是另一个"小说转视频"项目，与 DeterminFlow 不同；作为备选参考保留在 `.temp-ck/`。）

## 7. ACE-Step ——BGM 引擎，用得上

`ace-step/ACE-Step`（ACE Studio × 阶跃星辰）：开源音乐生成基础模型。**Apache-2.0**（商用干净）。v1 为 3.5B 参数（显存已优化到 **8GB**，`--cpu_offload true`），**v1.5 已于 2026-01 发布**；A100 上 20 秒出 4 分钟音乐；19 种语言歌词；支持 voice cloning/remix/伴奏分离等子任务；有 ComfyUI 节点与 **acestep.cpp**（GGML，CPU/CUDA/Metal/Vulkan 都能跑）。

**对本平台**：process 模块的 **BGM 引擎**（M3+）。管线：LLM 根据切片内容生成风格 tag → ACE-Step 生成纯音乐 → ffmpeg 混音（人声 BGM ducking）。配置需求：Python + 8G 显存 GPU（或 acestep.cpp 纯 CPU 慢跑）。✅ 已下载。

## 8. OpenShorts ——方向不同，但一个细节值得抄

`mutonby/openshorts`（**MIT**）：开源 AI 视频平台，三合一——Clip Generator（长视频→竖屏切片）、AI Shorts（AI 数字人 UGC）、YouTube Studio。自托管 Docker（8GB RAM，CPU 5-8 分钟出片，GPU 50 秒），自带 API key（Gemini/ElevenLabs/fal.ai），**自带 `/mcp` 端点**（Agent 可调用）。你判断对：方向是 AI 生成内容（UGC），与我们"搬运+直播+翻译"定位不同。
**值得抄的细节**：双说话人视频的**竖屏智能排版**——两人画面上下堆叠而非缩小、字幕放中缝、单人说话时人脸跟踪裁切，AI 自动选版式。这正是我们 process 模块"横转竖重排"要做的。✅ 已下载（90MB）。

## 9. Audio8 TTS ——0.1B 便携克隆 TTS，配音候选

**Audio8-AI/Audio8_TTS**（无界方舟 AutoArk）：0.6B 多语言零样本克隆 TTS（**Apache-2.0**）+ 最新 **0.1B Preview**（主模型 ~170M + codec ~120M，号称"最小可用的零样本 TTS"，zh/en/de/es/fr/it/ja/ko 8 语）。关键卖点：**官方提供 ONNX INT8 导出**（huggingface Audio8/audio8-TTS-0.1B-ONNX-INT8）→ CPU/端侧可跑。
**注意**：0.1B Preview 的 HF 页面标注 community-license-v1.0（非标准协议），0.6B 仓库是 Apache-2.0——**商用前核对清楚**。
**对本平台**：M3 配音引擎候选——极轻，Windows CPU 即可跑，适合批量解说配音；OmniVoice 的轻量备胎。**对观语**：ONNX INT8 形态理论上可端侧，但需验证移动端延迟与效果（当前 sherpa-onnx TTS 栈不动）。✅ 已下载代码仓库 + 模型卡存档。

## 10. OmniVoice ——声音克隆解说，主力候选

**正确地址 github.com/k2-fsa/OmniVoice**（你记的 `0mniVoice` 少了个 m，该地址不存在）。小米 AI 实验室下一代 Kaldi 团队 2026-04 开源：**0.8B 参数、600+ 语言、3-10 秒参考音零样本克隆、RTF 0.025（40 倍实时）、Apache-2.0**，扩散语言模型架构。支持 NVIDIA GPU / Apple Silicon / **Intel Arc（A310 4GB 有实测）**。

**重点回答"需要什么配置跑得动"**：
- 软件：Python 虚拟环境 + PyTorch（pip install omnivoice 即装）；模型从 HF 自动下载（国内用 hf-mirror.com）。
- 硬件：消费级 NVIDIA 卡 **8GB 显存稳妥**（0.8B 模型，fp16 约 1.6-2GB 权重+运行时开销）；实测下限更低（Intel Arc 4GB 亦跑通）。无 GPU 可走 HuggingFace Space/云端 API 验证效果。
- 旁证：**NarratoAI v0.8.6 直接提供 OmniVoice Windows 部署包**——说明 Windows 消费级部署已是成熟路径。

**"用你的音色生成解说"——可行**：录 3-10 秒干净人声 → 克隆 → 管线里 LLM 文案 + OmniVoice 配音 + ffmpeg 合成。对本平台：**M3 解说配音的主力引擎**（比 VoiceStudio 更干净的接入方式是直接 pip 调用或本地 WebUI API）。✅ 已下载。

## 11. ESP-Skainet ——本平台用不上，观语硬件线可能用上

`espressif/esp-skainet`（乐鑫）：**ESP32 系列芯片**上的唤醒词（WakeNet）+ 命令词（MultiNet，最多 200 条中英文离线指令）框架，推荐 ESP32-S3（8MB PSRAM）。
**"用麦克风控制我们的程序"判定**：❌ 对 Go 平台不适用——它跑在 ESP32 MCU 上，不在 PC。PC 端语音控制应走 **sherpa-onnx 的 KWS（唤醒词）+ 小型 ASR**（Go 直接调，观语同栈）或 Vosk。
**但**：观语的 **BLE 单词卡硬件**若用 ESP32-S3 主控，esp-skainet 就是现成的离线"唤醒+口令识别"方案（例如"下一个单词""复读"语音指令），值得在观语硬件线评估。

## 12. NarratoAI ——解说类内容管线的最佳参考

`linyqh/NarratoAI`（约 10K 星）：**AI 影视解说一站式工具**——LLM 写解说文案 → 自动剪辑 → 配音 → 字幕同步。2026-07 已到 v0.8.6，活跃。亮点：支持 **DeepSeek**；Qwen2-VL/TwelveLabs 视频理解选高光；**短剧解说/混剪**模式；TTS 支持 豆包/腾讯云/**IndexTTS-1.5 克隆**/**OmniVoice 部署包**；Fun-ASR 一键转录；**可导出剪映草稿**。
**配置需求**：Python 3.12（uv 管理）+ ffmpeg + LLM API Key（OpenAI 兼容，DeepSeek 直接填）+ 可选 TTS/视觉模型 Key。CPU 可跑（转码慢），无 GPU 依赖硬需求。
**对本平台**：它就是我们 M3"解说类内容"管线的完整 Python 先例——取其**管线编排、文案 prompt、字幕对齐策略**，用 Go 重做编排层。✅ 已下载。
